### Project Summary: DriverPass Management System
In this project, I acted as a systems analyst for **DriverPass**, a driver training company seeking to modernize their operations. The client required a web based, cloud hosted platform to help students prepare for DMV exams through online classes, practice tests, and a streamlined lesson booking system. My role was to design the architectural blueprint, ensuring the system supported multiple stakeholders (students, instructors, and administrative staff) while maintaining high availability and security.

### Strategic Approach to Software Design
My approach to designing software was rooted in a "Requirements First" strategy. I interpreted user needs by analyzing the specific pain points of each stakeholder, such as the IT officer's need for secure account management or the student's need for mobile access. Considering these needs is vital because it ensures the final product solves real business problems rather than just meeting technical specifications. For example, I integrated an API connection to the DMV to provide real-time rule updates, directly addressing a core client requirement. I believe I performed very well in the structural planning phase. I developed detailed UML Use Case and Activity Diagrams, and mapped out complex logic for tasks like lesson scheduling and secure password resets before any code was written. This rigorous design process ensures the system is robust and scalable. In the future, I plan to continue using iterative prototyping and relational database mapping to manage complex data relationships, such as those between students, vehicles, and training packages.

### Overcoming Challenges & Evolution
One of the primary roadblocks I encountered involved managing the project timeline under the reality of limited developers and strict time constraints. To address this, I utilized Agile processes like Daily Scrums to identify impediments in real time and pivot when requirements, such as a Mobile Appfeature, proved to be larger than initially expected. If I were to revise my work, I would improve the project Gantt chart by adding more granular task dependencies and buffer periods to better account for resource limitations. This project has evolved my perspective on creating maintainable and adaptable programs. By separating logic into modular components and prioritizing clear documentation, I’ve learned it is important to write code that is not only functional but also easy for future developers to scale.
